Ishaan's 8-bit CPU: An Interactive Simulator

A SystemVerilog CPU that I have built and verified from scratch. This page runs a JavaScript model of the exact same instruction set, faithful down to its real hardware attributes.

View the SystemVerilog source & testbenches on GitHub →

What exactly is this?

What I've built is a custom 8-bit CPU, designed and verified from scratch in SystemVerilog. Specifically, it's an accumulator-based processor with its own 16-instruction set, built module-by-module (full adder → ALU → register file → control unit → full datapath) and verified with self-checking testbenches, including an exhaustive 262,144-combination sweep of the control unit that turned up zero failures. This page doesn't run that SystemVerilog directly. Instead it runs a JavaScript model of the exact same instruction set, so you can try it without installing a simulator.

You'll also notice that some of the programs to load (or maybe even one you wrote) will eventually display red text telling you that the program cannot run. The CPU still did what it should, but I am still working at it to accomodate larger and larger programs. Check the github for when I commit updates!

How it works

  • Every instruction is 8 bits: a 4-bit opcode and a 4-bit operand.
  • There's a single accumulator, A. Almost every instruction reads a register, combines it with A in the ALU, and writes the result back to A.
  • 8 general-purpose registers, R0–R7, reached with LOAD/STORE.
  • A control unit decodes and fully executes one instruction per clock cycle - there's no multi-stage pipeline.
  • Two condition flags, Z and C, latch only when an arithmetic/logic instruction runs, and stay put otherwise - JZ/JC branch on whichever value they last latched.
  • JMP/JZ/JC targets are only 4 bits wide, so branches can reach addresses 0–15 - a real limitation of this instruction set, not something the simulator imposes.

What can you use this for?

  • Watch the CPU execute a real program instruction-by-instruction, with every register, flag, and the PC visible the whole time.
  • Write your own small programs with the built-in assembler (mnemonics, registers, and labels) and step through exactly what they do.
  • Load the four example programs - each one is a real test case that was actually used to verify the hardware design itself, including the exact operands that caught a real subtraction bug during development.

How to use this page

  1. New here? The page loads with "Adding two numbers" already in the editor — the comments in it walk through exactly what each line does. Otherwise, pick a different example from the dropdown, or write your own assembly.
  2. Click Assemble - it shows the raw hex bytes it produced, or an error if something's wrong.
  3. Click Step to execute one instruction at a time, or Run to let it go automatically (the slider controls speed).
  4. Watch PC / ACC / Z / C / R0–R7 update, the datapath diagram highlight which blocks are active that cycle, and the execution log describe exactly what each instruction did.
  5. Some programs read the Input value box - set it before stepping past an IN instruction, the same way you'd drive an input signal on a real testbench.
