Ishaan's 8-bit CPU: An Interactive Simulator

What this is (and what a CPU even is)

A CPU is the part of a computer that actually runs programs — it reads instructions one at a time and carries them out, over and over, extremely fast. Every computer and phone has one; this project is a working CPU built completely from scratch, as an actual digital circuit (not a program), to understand how one really works under the hood.

It was designed and tested in SystemVerilog, a language used to describe real hardware circuits. It's the same kind of process used to design actual chips. This is a simplified version: 8 bits wide, with 16 possible instructions, built and verified module by module (the full circuit design and test results are on GitHub). This page runs a separate JavaScript model of that same design, so you can watch it run without installing anything.

How it works

  • Every instruction is 8 bits: a 4-bit opcode (what to do) and a 4-bit operand (what to do the operation to).
  • There's a single accumulator, A. Almost every instruction reads a register, combines it with A in the ALU, and writes the result back to A.
  • 8 general-purpose registers, R0–R7, each holding one 8-bit number, reached with LOAD/STORE.
  • A control unit decodes and fully executes one instruction per clock cycle — there's no multi-stage pipeline.
  • Two condition flags, Z and C, latch only when an arithmetic/logic instruction runs, and stay put otherwise — JZ/JC branch on whichever value they last latched.
  • JMP/JZ/JC targets are only 4 bits wide, so branches can reach addresses 0–15 — a real limitation of this instruction set, not something the simulator imposes.

What you can use this for

  • Watch the CPU execute a real program instruction-by-instruction, with every register, flag, and the PC visible the whole time.
  • Write your own small programs with the built-in assembler (mnemonics, registers, and labels) and step through exactly what they do.
  • Load the four example programs. Each one is a real test case that was actually used to verify the hardware design itself, including the exact operands that caught a real subtraction bug during development.

How to use this page

  1. New here? The page loads with "Adding two numbers" already in the editor. The comments in it walk through exactly what each line does. You can pick a different example from the dropdown, or write your own assembly.
  2. Click Assemble. The built-in assembler turns your program into the raw hex bytes the CPU runs, or points out a specific error if something's wrong.
  3. Click Step to execute one instruction at a time, or Run to let it go automatically (the slider controls speed).
  4. Watch PC / ACC / Z / C / R0–R7 update, the datapath diagram highlight which blocks are active that cycle, and the execution log describe exactly what each instruction did.
  5. Some programs read the Input value box. Set it before stepping past an IN instruction, the same way you'd drive an input signal on a real testbench.

Glossary

Click any underlined term on this page to jump straight to its definition here.

CPU (Central Processing Unit)
The part of a computer that actually runs programs. It reads instructions one at a time, from memory, and carries each one out. Everything else (memory, screen, keyboard) exists to feed it work or show its results.
SystemVerilog
A hardware description language (HDL). Instead of writing a program that runs on a chip, you use it to describe the actual digital circuit of the chip itself (wires, logic gates, registers), which can then be simulated or manufactured. I have written and verified this CPU's design entirely in SystemVerilog.
Register
A small storage slot inside the CPU that holds exactly one number while it's being worked with. It's almost like a labeled box you can put a value in and take it back out later. This CPU has 8 of them (R0–R7), each holding one 8-bit number.
Accumulator
The CPU's main "working" register, usually just called A or ACC. Almost every operation in this CPU reads from or writes to it. Think of it as the number currently "in your hand" while you're doing arithmetic.
ALU (Arithmetic Logic Unit)
The part of the CPU that actually performs math and logic — addition, subtraction, AND/OR/XOR, shifting a number's bits left or right, and so on.
Opcode
The part of an instruction that specifies what to do ("add," "jump," "store," etc.) This CPU's opcode is 4 bits, giving exactly 16 possible instructions.
Operand
The part of an instruction that specifies what number/data to do the operation (from the opcode) to. This is usually which register to use, or which address to jump to.
Instruction / ISA (Instruction Set Architecture)
A single command the CPU understands (like ADD or JMP) is an instruction. The complete list of every instruction a CPU can execute is called its ISA, which is like the CPU's entire "vocabulary."
Program Counter (PC)
Keeps track of which instruction the CPU is currently executing like a bookmark in a book. It normally moves forward by one after every instruction, unless a jump instruction points it somewhere else.
Flag
A single true/false bit the CPU sets after certain operations, so later instructions can make decisions based on it. This CPU has a Zero flag (was the last result exactly 0?) and a Carry flag (did the last operation overflow, or need to borrow?).
Control Unit
The part of the CPU that reads the current instruction and decides, that instant, which other parts (the ALU, a register, the program counter, etc.) should be active, basically the CPU's traffic controller.
Datapath
The actual wires and components, like registers, the ALU, memory, etc. that a value physically flows through while an instruction executes.
Branch / Jump
An instruction that can make the CPU skip to a different instruction instead of simply moving to the next one in order. This is how loops and if/else-style decisions are built at the hardware level.
Assembler
A tool that translates human-readable instruction names (like ADD R0) into the raw binary/hex bytes the CPU actually reads and executes. This page has a small assembler built specifically for this project's instruction set.
Clock cycle
CPUs don't run continuously. They're driven by a repeating "tick" called a clock, and do a fixed amount of work on each tick. This CPU fully executes one instruction per clock cycle.
Hex (hexadecimal)
A base-16 number system (digits 0–9, then A–F) commonly used to write binary values more compactly than 1s and 0s. For example, the number 15 is written as F in hex, and 255 (the largest number this CPU's 8-bit values can hold) is FF.
